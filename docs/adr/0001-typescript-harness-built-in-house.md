# TypeScript benchmark harness built in-house

The v1 benchmark platform needs an evaluation harness. We chose to build it in-house in TypeScript, using OpenRouter's open-source `benchmark-harness` (Apache-2.0) as a structural reference only (CLI shape, benchmark registry, per-benchmark directories, epochs, retry, trace headers). We did not fork it, and we did not use Python. The generation layer (direct provider calls, and later a tokencamp Gateway seam) and the cost-accounting module are the parts this project must own for Task Economics — and they are exactly the parts of the reference repo that are coupled to OpenRouter's API internals; forking would drag in its Effect.ts stack and OpenRouter-specific machinery for little gain. Python's eval ecosystem is more mature, but it would split the codebase from the product's TypeScript stack.
